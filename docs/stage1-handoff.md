# Этап 1 «Ядро»: что готово и что проверить на живой системе

Код этапа 1 (шаги 1–13) лежит в ветке `stage1`. На сервер и в `main` ничего не выкладывалось. Всё проверено автотестами
на локальном Postgres (`npm run db:local`, 682 проверки, из них сквозная приёмка — `130_stage1_acceptance.test.sql`),
типами (`tsc`) и сборкой фронтенда. **Интерфейс и edge-функции на живой базе и GoTrue не запускались.**

## Порядок выкладки

1. Резервная копия и применение миграций, функций, настроек входа: `bash deploy/scripts/apply-stage1.sh --yes`
   (сначала без `--yes` — он покажет, что сделает). Скрипт идемпотентный, запускает проверку с откатом.
2. **Сохранить ключ шифрования** (`app.pii_key`), который скрипт покажет один раз при первом применении.
3. Добавить cron (раздел «cron» в `deploy/README.md`): статусы смен, сроки документов, явка и автоподтверждение,
   рейтинг, доставка уведомлений.
4. Задать переменные уведомлений (`MAX_BOT_TOKEN`, VAPID-ключи, `NOTIFY_CRON_SECRET`, `SITE_URL`), см. README.
5. Подтвердить с бухгалтерией налоговые ставки на `/admin/rules` (ИП, самозанятый, ГПХ, трудовой) и заведите утверждённые
   тарифы заказчиков — без них нельзя оформить заказ и принять перенесённые заявки.
6. Перенос старых заявок (на копии базы, затем на боевой):
   ```
   select * from private.migrate_legacy_requests();   -- перенос; повторный запуск ничего не дублирует
   select * from private.legacy_migration_report();   -- сверка: у всех строк ok = true
   ```
   Заявки без тарифа становятся «новыми» заказами и ждут тарифа; завершённые и прошедшие уходят в архив без смен.
7. Выложить фронтенд: слить `stage1` в `main` (после этого GitHub Actions выложит сайт).

## Что пройти руками после выкладки

| Сценарий | Роль | Что должно произойти |
| --- | --- | --- |
| Завести сотрудника, получить ссылку, задать пароль, войти, заблокировать | администратор | вход закрывается сразу |
| Включить двухфакторный вход для ролей с деньгами (`auth.mfa_enforced`) | администратор | вход требует код |
| Завести заказчика, тариф, объект, пройти чек-лист запуска | продажи, менеджер объекта | объект «Активен» |
| Оформить заказ с телефона из кабинета | заказчик | менеджер получает уведомление |
| Назначить людей, получить подтверждения | менеджер, исполнитель | сетка зелёная |
| Отметка на месте по геолокации и QR | исполнитель | вне радиуса отметка не проходит |
| Табель: отправить, оспорить строку, подтвердить остальное | менеджер, заказчик | подтверждённое блокируется |
| Бонус и крупное удержание | менеджер, руководитель | удержание больше порога ждёт согласования |
| Ведомости и маржа | руководитель, бухгалтер | суммы совпадают с ручным расчётом |
| Допуск кандидата (иностранец без патента не проходит) | рекрутер | задача по МВД создаётся |
