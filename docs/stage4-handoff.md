# Этап 4: доводка после приёмки этапа 3 (автономная работа)

Работа велась в ветке `stage4`, всё выложено на рабочий сервер и сайт (`main`). Каждая доработка заведена карточкой «Этап 4 · …» в колонке «Проверка» TickTick.

## Что сделано

**Качество и проверки**
- Сверка фронтенда со схемой базы (`scripts/frontend-contract.mjs`, входит в `npm run db:local`): все вызовы функций, таблицы и столбцы из `src/` существуют. Нашла 0 расхождений.
- Дымовые тесты страниц (vitest): 14 страниц этапа 3 на выдуманных ответах и 13 — на настоящих ответах живого сервера по демо-организации (`scripts/capture-fixtures.mjs`).
- Проверка живой системы на чтение (`npm run live:smoke`): вход под каждой ролью, вызовы функций, отказы там, где должны быть. Проверен и путь записи сделки под менеджером продаж (вставка, правка, запрет прямой смены этапа).
- Базовые проверки безопасности схемы (RLS на всех таблицах, `search_path` у всех функций `SECURITY DEFINER`).
- CI: красным было не наше: Docker Hub отвечал «toomanyrequests» при скачивании образов Supabase. Задача больше не блокирует, проверка идёт на `main` и `stage*`. (Раньше я ошибочно назвал причиной миграцию `realtime.messages`.)

**Производительность** (нагрузочная проверка `npm run bench`: 24 000 смен, 72 000 назначений, 68 000 начислений)
- Первое открытие дашборда за год: 141 с → 0,7 с; готовые агрегаты 0,28 с; БДР за год 0,3 с.
- Платёжный календарь: 6,9 с → 0,2 с; записи метрики: 5,3 с → 0,9 с; сетка планирования на месяц 0,05 с.

**Безопасность**
- Замок на пересчёт агрегатов: два одновременных открытия дашборда не ломают друг друга.
- Записи метрик с именами людей (активная база, удержание, найм) — только ролям, которые видят всех исполнителей/кандидатов (раньше менеджер продаж мог увидеть имена исполнителей).
- Календарь вахт требует доступа к назначениям.

**Функции**
- График выручки, маржи и укомплектованности за 12 месяцев; автообновление показателей раз в минуту.
- Настоящий Excel (.xlsx) во всех выгрузках (CSV остался для обмена с 1С и шаблонов импорта).
- Счета денег правятся из интерфейса (остаток на начало и его дата).
- Выигрыш сделки уведомляет менеджеров объектов (передача в ведение).
- Печатная форма табеля с подписями; выгрузка кандидатов.
- Стартовые страницы и меню по разделам для каждой роли.
- Журнал ошибок интерфейса (`/admin/errors`): браузеры сообщают об упавших страницах.

**Эксплуатация**
- Мониторинг раз в 5 минут (`ops-check.sh`): сайт, вход, база, свежесть бэкапа, диск, память, очередь уведомлений; оповещение администратору и руководителю.
- Проверка восстановления бэкапа (`verify-backup.sh`, раз в месяц). Найдено и записано: без `search_path = public, extensions` не восстанавливаются ограничения «без пересечений».
- Демонстрационная организация «ТЕСТ Демо-организация» с данными за 4 недели; тестовый исполнитель переведён в неё.
- Руководство по рабочим местам `docs/user-guide.md`.

## Вопросы к вам (накопились по ходу)

1. **Копия бэкапа на другой сервер.** Сейчас бэкапы лежат только на рабочем сервере: при его потере данные потеряются. Куда выгружать (другой сервер в РФ, облачное хранилище)? Нужен адрес и доступ.
2. **Банк и формат выписки.** Т-Банк или Точка? Нужен образец реального файла `kl_to_1c.txt` и образец файла платёжных поручений, который принимает ваш интернет-банк.
3. **Платформа выплат самозанятым** (Консоль.Про, Наймикс, Jump.finance, Рокет Ворк) — какая; без неё выплаты самозанятым идут вручную.
4. **ЭДО** (Диадок, СБИС) и **формат обмена с 1С** (сейчас таблицы CSV; нужен ли EnterpriseData).
5. **Налоги в БДР:** режим организации (УСН 6% / 15% / ОСНО), НДС, какие ставки у исполнителей-самозанятых, ГПХ и по трудовому договору (в ТЗ помечены «не подтверждено»).
6. **Почта.** Нужна ли серверная отправка писем (КП, восстановление пароля, приглашения)? Для этого нужен SMTP-сервис. Пока КП открывается в почтовой программе сотрудника.
7. **MAX-бот** для уведомлений сотрудникам: у сотрудников должны быть привязаны чаты, иначе уведомления (в том числе служебные оповещения о сбоях) приходят только в ленту системы.
8. **Параметры, принятые мной по умолчанию — подтвердите или поправьте:** вероятности этапов воронки 10/25/40/60/80%; «новый заказчик» — заведён за последние 3 месяца; выплаты исполнителям раз в неделю по пятницам за смены старше 3 дней; удержание считается как «работал через N дней после допуска»; суточные вахты начисляются по месяцам.
9. **Вахты:** как у вас реально считаются суточные и проезд (по дням или по заездам, облагается ли), кто оплачивает жильё.
10. **Формула рейтинга исполнителя** (открытый вопрос ТЗ).
11. **Реальные данные:** какие таблицы сейчас ведут отделы (форматы), чтобы подготовить шаблоны импорта под них.
12. **Сервер:** в ТЗ заложено 4 ГБ (этап 2) и 8 ГБ (этап 3); сейчас 2 ГБ, свободной памяти ~0,9 ГБ. Когда расширяем?
13. **Демо-организация:** оставить для обучения или убрать перед запуском?
14. **Список обязательных документов** по типам объектов и позициям (медкнижка и т. п.) — для настройки допуска.

## Что пройти руками

Зайдите под тестовыми аккаунтами (переключатель организации → «ТЕСТ Демо-организация») и пройдите сценарии из `docs/user-guide.md`. Любые падения страниц сами попадут в «Журнал ошибок» (админ/руководитель); визуальные замечания присылайте списком.
